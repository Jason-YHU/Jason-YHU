The syllabus explicitly wants you to describe and use a hashing algorithm — your notes only say "use a hashing algorithm" without one:
Hashing algorithm A calculation that converts a record's key directly into a storage address, so the record can be found without searching.
Simplest method — division/remainder (modulo)
address = record key MOD number of storage locations
Worked example 10 storage locations (addresses 0–9). Record key = 1023.
1023 MOD 10 = 3 → the record is stored at (or looked up from) address 3.
Collisions Two different keys can hash to the same address (e.g. 1013 MOD 10 = 3 too) — this is a collision. A common fix is to store the second record in the next free slot (linear probing) and search forward from the "expected" address if it's not there when retrieving.
Key MOD 10 gives the address. When two keys land on the same address, linear probing puts the second record in the next free slot.

13.3 Floating-Point Numbers

high-yield
Definition A floating-point number is stored as two parts: the mantissa (M), which holds the significant digits, and the exponent (E), which says how far to shift the binary point. Both are stored as fixed-length two's complement binary strings.
Formula
value = M × 2E
How the 16 bits split. The mantissa's first bit is the sign; the binary point is implied straight after it. Both fields are two's complement.

Binary → Decimal

Shift the mantissa's point right by E places if E is positive (left if E is negative), then convert to decimal.

Worked example — positive number M = 0.1011010, E = 00000100 (= 4)
Shift right by 4: 1011.010 = 8+2+1+0.25 = 11.25
Worked example — negative mantissa M = 1.1110100 (MSB = 1, negative), E = 00000100 (= 4)
Magnitude: invert + 1 → 0.0001100, shift right 4: 0001.100 = 1.5 → −1.5
Worksheet practice — large positive exponent M = 0.1110010, E = 00000111 (= 7)
Shift right by 7: 01110010. = 64+32+16+2 = 114

Decimal → Binary

  1. Convert the whole-number part and fractional part to binary separately, and combine.
  2. Normalise so the point sits in the required position — count how many places you shift it.
  3. Adjust E by that many places, then write M and E as fixed-length two's complement binary.
Worked example — 4.5 4 = 0100, 0.5 = .1 → 0100.1
Normalise: move point left 3 → 0.1001, E increases by 3
M = 0.1001000, E = 00000011
Worked example — pure fraction, 0.375 0.375 = 3/8 = 0.011 = 0.11 × 2−1
M = 0.11, E = −1 (two's complement 11111111)

The subtle bit It's tempting to two's-complement only the fractional digits and leave the leading bit as 0 — that gives a mantissa starting "0.1…", which looks like a positive pattern and is wrong. The sign bit must be included in the invert-and-add-1 step.

Normalisation

high-yield
Rule A mantissa is normalised when its first digit after the point differs from the sign bit:
Positive number01…
Negative number10…
Shift rule Moving the point left one place → E increases by 1. Moving it right → E decreases by 1.
Why normalise? (two reasons) 1. It gives every number exactly one valid representation — without it, the same value could be written many different ways, which is ambiguous.
2. It maximises precision, using every available mantissa bit for significant digits instead of wasted leading 0s/1s.

Edge case worth knowing: zero itself cannot be written in strictly normalised form (0.0000000 doesn't satisfy either pattern above) — it's the one value systems must special-case.

Precision versus Range

Key trade-off More mantissa bits → greater precision. More exponent bits → greater range.

e.g. for high accuracy but low range: allocate a large mantissa and a small exponent (and vice versa for high range but low accuracy).

Your notes don't cover the limitations of floating-point representation — a syllabus point on its own:
Approximation & rounding errors Not every real number can be represented exactly in binary floating point — e.g. 0.1 in binary is a recurring fraction (0.0001100110011…). Since only a fixed number of mantissa bits are available, the stored value must be rounded to the nearest one that fits, creating a small rounding error between the true value and what's actually stored.
Overflow Occurs when a number's magnitude is too large to be represented, even using the largest available exponent.
Underflow Occurs when a number's magnitude is too small (too close to zero) to be represented, even using the smallest available exponent — it effectively rounds down to zero.

RISC versus CISC

high-yield
CISC — Complex Instruction Set ComputerRISC — Reduced Instruction Set Computer
Emphasis on hardware. Aim: do a task in as few lines of assembly code as possible. Emphasis on software. Aim: break the task into simpler instructions that each run very fast.

Clarified Your RISC/CISC flowchart says CISC has a "small size of instructions" and RISC a "bigger size". That's about the program, not each instruction: CISC programs are shorter (fewer, more powerful instructions), RISC programs are longer (more, simpler instructions) — but each RISC instruction is quicker to decode and execute. Also, on page 15, "every ? takes one clock cycle" should read "every instruction takes one clock cycle".

Pipelining

Definition Pipelining lets several instructions be processed at the same time, each at a different stage of the fetch–execute cycle.

RISC uses five stages: IF instruction fetch · ID instruction decode · OF operand fetch · IE instruction execute · WB write back result.

Without pipelining, 5 instructions × 5 stages = 25 cycles. With pipelining they finish in 9 cycles: a new instruction completes every cycle once the pipe is full.
Syllabus wording: understand the importance of registers in RISC. Because RISC has many registers, operands are usually already in a register, so the OF stage doesn't have to wait on slow main memory. That's what keeps the pipeline flowing at one instruction per cycle.

Interrupts in a pipeline

When an interrupt arrives, up to five instructions are part-way through the pipe. Two options:

  1. Flush: discard everything in the pipeline except the instruction in the WB stage, handle the interrupt, then restart from the next instruction in sequence.
  2. Save: store the contents of all five stages in registers, handle the interrupt, then restore the pipeline to exactly where it was.
The syllabus asks for interrupt handling on CISC too: a CISC processor finishes the current (possibly multi-cycle) instruction first, then saves the registers and jumps to the interrupt service routine. It's simpler but responds more slowly, because one instruction can take many cycles.

The four basic computer architectures

Read the name as Single/Multiple Instruction, Single/Multiple Data. Highlighted: SIMD and MIMD are the ones most used in parallel systems.
ArchitectureHow it works
SISDOne processor, one instruction on one data item at a time, in sequence. No parallel processing.
SIMDMany processors all run the same instruction on different data. Also called array processors — e.g. brightening every pixel of an image at once.
MISDMany processors, each running a different instruction on the same data. Rarely used.
MIMDMany processors, each with its own instructions and its own data (memory may be partitioned). Used in multicore systems.

Parallel processing & massively parallel computers

  • Processors must communicate and share data, so dual core ≠ 2× performance.
  • Software (and the programming language) must be written to support parallel processing.
  • Faster for processing large volumes of independent data, but needs more expensive hardware.
  • Overcomes the Von Neumann bottleneck (one processor fetching one instruction at a time over one bus).
Massively parallel computers Many computers (often SIMD processors) linked together as a cluster, acting as one huge pseudo-parallel system — effectively a supercomputer with several thousand processors working on one problem at the same time.

Each guest OS thinks it owns a whole computer. The hypervisor sits between it and the real hardware, so a crash inside a VM can't reach the host.

Benefit: if the new OS crashes, the host isn't affected. Limitation: it runs slower than on real hardware, so performance testing isn't realistic.

16.1 Purposes of an Operating System

Hiding the complexity of the hardware

  • A GUI instead of a command line interface.
  • Device drivers simplify the interface to hardware.
  • Simplifies saving and retrieving data from memory and storage devices.
  • Runs background utilities (e.g. virus scanning) that the user can leave to look after themselves.
Also on the syllabus: how an OS maximises the use of resources. It keeps the CPU busy by switching to another process whenever one waits for I/O, allocates memory so as many processes as possible fit, and uses DMA so data transfers don't tie up the CPU.

Process management

Multitasking Lets a computer appear to carry out more than one task/process at a time. A process is a program that has started executing.
Pre-emptiveNon-pre-emptive
Resources are given to a process for a limited time. A running process can be interrupted (e.g. a higher-priority process arrives). More flexible, but low-priority processes may be starved. Once a process has the CPU it keeps it until it finishes its burst or blocks/voluntarily gives up control. More rigid; a long process can starve shorter ones.

Process control block (PCB)

Definition A data structure holding all the data needed for a process to run. Each process has its own PCB, and the CPU registers (PC, MAR, MDR, ACC) are saved to it when the process stops running.

It stores: current process state · process ID · privileges (resources it may access) · register values · priority and scheduling information · CPU time still needed.

A process's priority depends on: its category (batch, online, real-time) · whether it's CPU-bound (long CPU bursts, short I/O) or I/O-bound (short CPU bursts, long I/O) · resource requirements · turnaround, waiting and response time · whether it can be interrupted. After priority is set it can still be affected by deadlines, CPU time needed, wait time and memory requirements.

Memory management

Decides which processes should be in main memory and where; allocates and deallocates memory as needed.

PagingSegmentation
Memory split into fixed-size blocks (not necessarily contiguous): logical blocks = pages, physical blocks = frames. Logical address space split into variable-size blocks called segments, each with a name and a size.
A page table (page number, flag status, frame address, time of entry) maps logical → physical addresses. A segment map table (segment number + size) maps logical → physical: address = segment number + offset.
Hardware decides the page size; invisible to the programmer. User gives one value (the address). Visible to the programmer; user gives two values (segment number and offset).
Fixed size → internal fragmentation (last page not fully used). Variable size → less internal but more external fragmentation.
Not in your notes, but on the syllabus:
Virtual memory Secondary storage used as an extension of RAM. Only the pages a process needs right now are kept in RAM; the rest wait on disk and are swapped in when needed.
Page replacement When RAM is full and a new page is needed, one page is swapped out. Common rules: FIFO (oldest page out — uses "time of entry" in the page table), LRU (least recently used out).
Disk thrashing Pages are swapped in and out so often that the system spends more time moving pages than running processes, and performance collapses.
Kernel as interrupt handler The kernel handles interrupts (e.g. timer at the end of a time slice, I/O complete). Each interrupt triggers low-level scheduling: save the PCB of the current process, then choose which ready process runs next.

Backus-Naur Form (BNF)

Definition BNF is a meta-language: a special language used to define the syntax (grammar) of a programming language unambiguously.
SymbolMeaning
< >encloses an item (a non-terminal)

Example (from your slide) <digit> ::= 1|2|3
<letter> ::= A|B|C
<variable> ::= <letter><digit> — a variable is a letter followed by a digit.
Each rule is a production. A recursive definition lets a rule refer to itself: <variable> ::= <letter>|<variable><letter> means "any number of letters".

Reverse Polish Notation (RPN)

high-yield
Definition RPN is postfix notation: operands first, then the operator. Infix a + b → prefix + a b → postfix (RPN) a b +.
Operators sit on the branches, operands on the leaves. A post-order traversal of the tree gives the RPN directly.
Conversions a + b × c → a b c × + (× first, so it comes first) ✓ your notes
(a + b) × (c − a) → a b + c a − ×
(a + b) − x ^ y × 3 → a b + x y ^ 3 × − (^ before ×, × before −)
Why use RPN? Unambiguous; read and evaluated strictly left to right; no brackets needed; no need for operator precedence rules. It's evaluated with a stack: push operands; on an operator, pop two, apply, push the result.
Evaluating with a stack — a b + c a − × with a = 2, b = 3, c = 7 push 2 · push 3 · + → pop 3, 2, push 5 · push 7 · push 2 · − → pop 2, 7, push 5 · × → pop 5, 5, push 25
A unary operator needs only one operand (e.g. the minus in −3). It's applied before everything else.
Not in your notes, but on the syllabus:
Interpreter Translates and executes the source code one statement at a time. It never produces a separate translated (object code) file, which is why it must be present every time the program runs.
Stages of compilation 1. Lexical analysis: removes whitespace/comments, splits code into tokens, builds the symbol table.
2. Syntax analysis: checks the tokens follow the grammar (BNF rules); builds a parse tree.
3. Code generation: produces object code.
4. Optimisation: makes the code use less memory or run faster.

19.1 Algorithms

Linear search

Check each item in turn, from the start, until the key is found or the list ends. Works on unsorted data.

Pseudocode 
Index ← 0
Found ← FALSE
WHILE Found = FALSE AND Index < Length
    IF List[Index] = Key THEN
        Found ← TRUE
    ELSE
        Index ← Index + 1
    ENDIF
ENDWHILE

Binary search

high-yield

Condition: the data must be sorted. Look at the middle item and discard the half the key can't be in.

Each pass throws away half of what's left. 5 items need at most 3 passes; 1000 items need at most 10.
Three cases each pass (mid = (lower + upper) DIV 2) x[mid] = key → found
x[mid] < key → key is to the right → lower ← mid + 1
x[mid] > key → key is to the left → upper ← mid − 1
Loop WHILE key not found AND lower ≤ upper.
Corrected Your notes have the two update rules swapped: "x[mid] > key → change lower to mid + 1" and "x[mid] < key → change upper to mid − 1". It's the other way round (see the box above). Your worked example (9 < 12 → change lower bound) was right, so trust that. Also the loop condition is lower ≤ upper, not lower < upper, or you'd miss the key when one item is left.
Recursive version (your slide, tidied) 
def binSearch(x, low, up, key):
    if low > up:
        return "not found"
    mid = (low + up) // 2
    if x[mid] == key:
        return mid
    elif x[mid] > key:
        return binSearch(x, low, mid - 1, key)
    else:
        return binSearch(x, mid + 1, up, key)

Big O notation

AlgorithmBest caseWorst case
Linear searchO(1) — first itemO(n) — last item or not there
Binary searchO(1) — middle itemO(log₂ n) — halves each pass

Big O describes how time (or memory) grows as the number of items n grows — it's how you compare two algorithms that do the same job. Doubling the data adds one extra pass to a binary search but doubles the work for a linear search.

Bubble sort Repeatedly pass through the list, swapping adjacent items that are in the wrong order. Stop when a pass makes no swaps. Worst case O(n²); fast if the data is nearly sorted (with the "no swaps → stop" flag).
Insertion sort Take each item in turn and insert it into the correct place in the already-sorted part to its left. Worst case O(n²); very fast on nearly sorted data.

Graph — nodes (vertices) joined by edges, can be weighted/directed; used for maps and networks (no code needed). Any of these can be built from arrays/records, or from another ADT (e.g. a queue from a linked list).

19.2 Recursion

high-yield
Definition Recursion: a function or procedure that is defined in terms of itself and calls itself.
Base caseGeneral case
A terminating solution that is not recursive. e.g. 0! = 1 A solution defined recursively — it moves towards the base case. e.g. n! = n × (n − 1)!
Factorial in pseudocode 
FUNCTION Factorial(n : INTEGER) RETURNS INTEGER
    IF n = 0 THEN
        RETURN 1                       // base case
    ELSE
        RETURN n * Factorial(n - 1)    // general case
    ENDIF
ENDFUNCTION

Winding and unwinding

WindingUnwinding
The recursive function keeps being called until the base case is reached.Once the base case is reached, each call returns its value, back down the chain.
Each call pushes a frame (return address + local variables). The base case stops the pushing; the returns then pop the frames in reverse order.

How a compiler implements recursion

  • Uses a stack.
  • Winding: the object code pushes the return address and the values of local variables onto the stack with each recursive call.
  • Unwinding: the object code pops the return address and local variables off the stack.

When to use recursion

BenefitsDrawbacks
Less code than an iterative solution.
Solves some complex problems (trees, divide-and-conquer) more simply.		 Many recursive calls use a lot of stack memory, which can cause a stack overflow.
Usually slower than iteration (overhead of each call).
Self-testWhat happens if a recursive function has no base case?
It never stops calling itself; the stack fills up and overflows.
Self-testWhat two things are pushed onto the stack for each call?
The return address and the values of local variables.
